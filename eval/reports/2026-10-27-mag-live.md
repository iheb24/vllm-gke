## Exact commands for the live session

```bash
# 1. Port-forward the Envoy gateway (model traffic)
export ENVOY_SERVICE=$(kubectl get svc -n envoy-gateway-system \
  --selector=gateway.envoyproxy.io/owning-gateway-namespace=vllm,gateway.envoyproxy.io/owning-gateway-name=semantic-router \
  -o jsonpath='{.items[0].metadata.name}')
kubectl port-forward -n envoy-gateway-system svc/$ENVOY_SERVICE 8081:80 &

# 2. Env (never commit the key)
export GATEWAY_API_KEY=$(kubectl get secret vllm-api-key -n vllm -o jsonpath='{.data.key}' | base64 -d)
export GATEWAY_URL=http://localhost:8081/v1
export GATEWAY_MODEL=Qwen/Qwen2.5-Coder-14B-Instruct-AWQ

# 3. Start the demo WITHOUT the fake model (live mode), fresh local db
rm -rf showcases/mag/data
.venv-showcases/bin/uvicorn app:app --port 8093 --app-dir showcases/mag &

# 4. Smoke check, then the Alice/Bob walkthrough from showcases/mag/README.md
curl -s http://localhost:8093/healthz

# 5. Scenario eval against the live model (fresh db: restart the app or
#    use delete-all per eval user first)
.venv-showcases/bin/python eval/run_mag_eval.py \
  --url http://localhost:8093 \
  --scenarios eval/showcases/mag_scenarios.yaml \
  --report eval/reports/$(date +%F)-mag-live.md \
  --note "Live run: $GATEWAY_MODEL via Envoy gateway (kubectl port-forward)."
```

Note on scenario idempotency: the scenario set asserts exact memory counts,
so run it against a fresh database (step 3) or delete-all for each
`eval-*` user between runs. The GPU tier may cold-start for several
minutes on the first request after an idle period; that is expected.
